# 开发提示词（修订版 · 可直接复制）

> 本文件是对《A股国家队资金监控平台_开发提示词整理文档》的**完善版**，吸收了
> 《完备性与精准性研判》的全部 P0/P1 修订。原版 5 个模块结构保留，但
> **删除了「实时/准实时跟踪国家队交易行为」「个股层面国家队加仓机会筛选」等
> 在公开数据下无法成立的承诺**，改为「三层监控 + 带置信度的概率推断」。
>
> 使用顺序：先粘贴【全局前置约束】→ 再按模块一到五逐个使用。
> 「可直接复制」区块内为提示词正文。

## 【全局前置约束】· 必须最先粘贴

```
【全局前置约束 · 数据可得性与口径，优先级高于后文所有模块】

1. 前提：A 股「国家队」无官方固定名单，官方不实时披露任何主体的盘中下单，
   公开数据无法日频归因到具体国家队主体。禁止假设能获取「国家队日频交易流水」。
   所有输出必须标注数据层级与可信度：
   L1 实测（季度/半年度：上市公司十大流通股东、ETF 半年报/年报前十大持有人）；
   L2 估算（T+1：宽基 ETF 每日总份额变动 × 当日净值 = 全市场一级市场净申购，
       不可识别申购人）；
   L3 代理/交叉验证（央行/汇金/证监会/国资委/国新·诚通公告、互换便利、
       回购增持再贷款额度、融资余额、成交额）。
   估算类指标必须同时输出置信度与误差来源，禁止表述为「国家队买入 X 亿元」。

2. 主体清单（按披露账户名，非集团名）：
   核心：中央汇金投资、中央汇金资产管理、中国证券金融股份有限公司
        （= 证金公司 = 中证金公司，同一实体不得重复计数）、
        中证金融资产管理计划（10 只）、证金资管；
   扩围：中国国新（国新投资、国新宏盛）、中国诚通（诚通金控、诚旸投资、诚通资本）；
   外汇局系：梧桐树投资平台、北京凤山投资、北京坤藤投资；
   长线配置（单列，不与托底资金混算）：全国社保基金及各组合、基本养老保险基金。
   排除：中国投资有限责任公司（中投，主权财富基金，主司境外投资）。
   必须建立「账户别名 → 标准主体 ID」映射表，按最长别名优先匹配，兼容简称与历史更名。

3. 时点防前视（PIT）：所有持仓记录含 report_period（季度标签）、
   report_period_end（报告期末 ISO 日期）、disclose_date（实际披露日）、
   effective_date（策略最早可用日 = 披露日）。回测与信号只允许使用
   effective_date <= as_of 的数据；季报更正/追溯调整保留版本链，不覆盖历史快照。

4. 清洗硬规则：
   a) 十大股东名单「新进/退出」≠「增持/减持」，被挤出前十须单独标记，
      不计入主动增减持；
   b) 持股数变动须按送股、转增、配股、增发、回购注销做复权调整，剔除被动变动；
   c) 「十大股东」与「十大流通股东」分开存储与统计，禁止混用；
   d) 估算市值统一按报告期末收盘价，另保留「区间成交均价」口径供敏感性对比。

5. 术语表（先输出再编码）：国家队、净申购额、名单进出、持股变动、PIT 时点、
   托底信号、政策底。任何「指数」类指标必须给出完整公式、归一化方法、阈值与方向。

6. 信号铁律：任何信号的 is_confirmed 恒为 False；基于 L2 的推断置信度上限为 medium；
   输出必须包含 attribution（无法归因到具体主体）与 caveat（政策底≠市场底、
   历史间隔 40 天至 6 个月、系统不提供个股买卖建议）。

7. 回测约束：明确基准指数、考虑交易成本与涨跌停/停牌不可成交、划分样本内/样本外、
   披露事件样本数量与过拟合风险；对照「纯跟随 vs 指数基准 vs 叠加二次过滤」三组结果。

8. 合规与免责：说明各数据源授权要求（Wind/iFinD 商业授权、公开页面频控与版权）、
   数据仅用于研究、所有输出不构成投资建议；页面固定展示免责声明。

9. 交付契约：先输出术语表与数据字典、一条真实样例记录及其解析结果、
   验收标准与测试用例，再输出代码；代码附依赖版本、配置/密钥管理、启动命令
   与「如何验证跑通」的步骤。凭据只从环境变量读取，不落盘、不打印、不进日志。
```

```
你是一个专业的量化金融系统架构师兼全栈工程师，请设计并开发一个
「A 股国家队资金三层监控看板」。

核心目标（注意：不是跟单系统）：
按 L1 实测 / L2 估算 / L3 代理三层，跟踪与稳定市场相关的公开信息，
输出「是否出现托底信号」的概率判断与置信度，供人工做进场与仓位决策参考。
严禁输出个股买卖建议、目标价、荐股措辞；严禁把 L2 估算表述为国家队实盘买入。

单页 HTML/ECharts；调度用标准库，避免额外中间件。
先给出整体架构图（文字描述）、数据表设计与 API 契约，再分模块给实现建议。

## 模块二 · 数据获取与清洗提示词（修订版）

```
请为「国家队资金三层监控看板」设计数据获取与清洗方案。

数据源必须按三层组织（这是原版最大的缺口）：
- L1 实测：上市公司十大流通股东/十大股东（季报/半年报/年报）、
  ETF 半年报与年报前十大持有人。注意 ETF 季报常只标「机构 1、机构 2」，
  须对照上年年报推断，且披露滞后约 20 天至 1-2 个季度。
- L2 估算：交易所/基金公司/行情平台每交易日盘后公布的宽基 ETF **总份额**
  （核心池：510300、510050、510500、512100、588000、159915）。
  净申购额 = 份额增量 × 当日净值。**看份额，不看成交额**：二级市场买卖不改变总份额。
  必须标注「无法识别申购人；保险、公募自营、外资、国有资本都可能申购」。
- L3 代理：中国人民银行、中央汇金、证监会、国资委、中国国新、中国诚通官网公告；
  巨潮资讯；互换便利与回购增持再贷款额度；融资余额、成交额。

明确排除：行情软件「主力资金流入/国家队资金流向」指标（无法确认买方身份）、
龙虎榜所谓「国家队席位」、网传「今日买入清单」。

请回答并实现：
1. 每层数据源的更新频率、延迟、授权与合规要求（Wind/iFinD 需商业授权；
   公开页面需遵守频控与版权）。
2. 设计数据库表结构：market_daily、etf_daily、announcements、holdings、
   signals、alerts、meta。holdings 必须含
   report_period / report_period_end / disclose_date / effective_date。
3. 给出主体别名映射表与 normalize() 实现，并写一条测试证明
   「中国证券金融股份有限公司」「证金公司」「中证金公司」归一到同一 ID。
4. 给出 Python 代码：演示数据生成器（固定随机种子、字段与真实 schema 一致、
   is_demo=True、页面需显示警示）+ LiveAdapter 骨架（默认禁用、标注未核验）。
5. 实现四条清洗硬规则并各配一个单元测试：名单进出、复权、口径分离、PIT 防前视。
6. 调度：每交易日盘后（默认 16:30）刷新；提供 crontab 与容器内线程两种方案。

## 模块三 · 指标与信号设计提示词（修订版）

```
基于三层数据，设计「托底信号」判定系统。禁止设计「国家队净买入金额」
这类不可观测量；禁止把 ETF 净申购额归因到国家队主体。

核心指标（全部可复现、可单测）：
1. 宽基 ETF 估算净申购额（L2）：sum(份额增量 × 净值)，单位亿元；
   同步净申购只数 = 当日 est_net_yi > 0 的 ETF 数量。
2. 市场跌幅（L3 辅助）：当日涨跌幅、近 5 日累计涨跌幅。
3. 官方增持类公告计数（L3）：近 N 日 is_supportive=True 的公告条数。
4. 托底信号（三重共振），给出完整公式/阈值/方向：
   条件① 当日 ≤ -1.5% 或 近 5 日 ≤ -4.0%
   条件② 同步净申购只数 ≥ 3 且 合计净申购额 ≥ 200 亿元
   条件③ 近 5 日存在增持/稳市类官方公告
   三者齐备 → POLICY_BOTTOM_PROBABLE（置信度 medium）
   仅② → INFLOW_ONLY（低）：只记为「有大额增量资金承接」，不标记为国家队的队进场
   仅③ → ANNOUNCEMENT_ONLY（低）：公告表达政策意图，额度≠实际买入
   其余 → NO_SIGNAL（低）

铁律：is_confirmed 恒为 False；confidence 不得为 high；
每条信号必须带 attribution、summary、conditions（逐条 met/detail）、caveat
（政策底≠市场底、历史间隔 40 天至 6 个月、不提供个股买卖建议）。

请给出：指标计算公式、状态机、Python 实现（不强制 Pandas，标准库即可）、
以及至少 8 个单元测试（含单只 ETF 放量不算同步、5 日跌幅单独满足、
任何状态下 is_confirmed=False）。

回测：信号盘后生成，最早入场时点为下一交易日收盘（PIT）；
输出事件数、胜率、平均前瞻收益、最大回撤、指数买入持有对照；
必须附「国家队进场事件为个位数样本、极易过拟合」的样本量警示。
```

## 验收标准（原版完全缺失，本版新增）

| # | 验收项 | 判据 |
|---|--------|------|
| 1 | 主体去重 | 证金系列别名全部归一到同一 ID；核心主体中该实体只出现一次 |
| 2 | 中投排除 | `normalize("中国投资有限责任公司")` 返回 excluded |
| 3 | 名单进出 | 新进/退出名单的分类为「不可判定」，不进入增减持统计 |
| 4 | 复权 | 10 转 3 导致持股数 +30% 判为「被动变动」，不计入主动增持 |
| 5 | PIT | `assert_no_lookahead` 对晚于 as_of 的持仓记录抛错 |
| 6 | 信号铁律 | 所有状态 `is_confirmed=False`；三重共振置信度 ≤ medium |
| 7 | 可复现 | 相同种子两次生成演示数据完全一致 |
| 8 | API 契约 | 全部接口字段与 `docs/DATA_DICTIONARY.md` 一致 |
| 9 | 前端降级 | 后端不可达时页面显示提示，不白屏、不抛未捕获异常 |
| 10 | 合规 | 页面固定免责；无凭据落盘；无荐股措辞 |

> 本项目已按上述提示词实现，对应测试见 `tests/`，自检命令 `python -m ntm check`。
